6. Reproducing the build from scratch
-------------------------------------

After the toolchain above is in place (and openvr submodule initialized via
`git submodule update --init --depth 1 openvr`):

    cargo xtask prepare-deps --platform windows --ci
    cargo xtask prepare-deps --platform android --ci
    cargo xtask build-streamer --release
    cargo xtask build-client   --release

Deploy the client to a connected Quest / Pico / etc:

    adb install -r build/alvr_client_android/alvr_client_android.apk
    adb shell am start -n alvr.client.dev/android.app.NativeActivity
    adb logcat -s ALVR:*

Register the streamer with SteamVR (one-time):

    "C:\Program Files (x86)\Steam\steamapps\common\SteamVR\bin\win64\vrpathreg.exe" `
        adddriver "D:\projects\alvr\build\alvr_streamer_windows"


7. Known gotchas encountered during initial setup
-------------------------------------------------

- Build Tools without ATL: the Intel VPL encoder (cpp/platform/win32/VideoEncoderVPL.h)
  pulls in <atlbase.h>. The default VCTools workload does NOT include ATL —
  add Microsoft.VisualStudio.Component.VC.ATL and .ATLMFC explicitly.

- vs_installer.exe vs setup.exe vs vs_BuildTools.exe (bootstrapper):
  Only the bootstrapper (downloaded fresh from aka.ms/vs/17/release/vs_buildtools.exe)
  honors --wait properly. vs_installer.exe and setup.exe both return immediately
  even with --wait, regardless of whether the modify is finished.

- Chocolatey 2.x rejects empty checksums by default. pkgconfiglite has no checksum
  in its package — install with --allow-empty-checksums for that package only.

- choco install crashes mid-batch after the LLVM installer's PATH broadcast (the
  next package in the same elevated session never starts). Workaround: install
  LLVM alone, then run a second elevated choco invocation for the rest.

- sdkmanager --licenses is interactive even with stdin piping. Pre-populate
  $ANDROID_HOME\licenses\ with the well-known hashes to bypass entirely.

- cargo-apk needs ANDROID_HOME (the SDK), not just ANDROID_NDK_HOME (the NDK).
  Easy to miss because the ALVR README's Android section only talks about the NDK.

- ALVR's `.cargo/config.toml` forces `+crt-static` for x86_64-pc-windows-msvc.
  This means even host-built proc-macros need the MSVC linker; the GNU `link.exe`
  shipped under Git Bash's /usr/bin masks the MSVC one if your shell PATH puts
  /usr/bin ahead of the VS install. cargo's auto-detection via vswhere works fine
  once VS is registered, so this only bites if you try to invoke link.exe by name.
